# meta-os-plugin — development contract

This repository builds the meta-os plugin for Claude Code. This file is for work on the repository itself. It is not shipped: a `CLAUDE.md` inside a plugin is not loaded and fails strict validation, so none may exist under `plugin/`'s root.

## Layout

| Path | What | Shipped |
|------|------|---------|
| `plugin/` | The plugin: manifest, skills, `bin/`, scripts, the instance template | yes |
| `plugin/.claude-plugin/plugin.json` | The manifest; `version` is the one place the version is written | yes |
| `plugin/bin/meta-os` | The command; it finds the plugin folder from its own location | yes |
| `plugin/scripts/meta_os/` | The command's code: `init`, `doctor` | yes |
| `plugin/skills/` | Skills, called as `/meta-os:<folder>`, each with its own `references/` or `resources/` | yes |
| `plugin/systems/` | Reference documents, the skill catalog and the agent roster; never copied into an instance | yes |
| `plugin/PROVENANCE.md`, `plugin/LICENSE` | Origin and licence of what ships, third-party notices included | yes |
| `plugin/instance-template/root/` | What `init` writes into an instance, path for path | yes |
| `.claude-plugin/marketplace.json` | The marketplace file used until the plugin is listed elsewhere | no |
| `tests/`, `scripts/`, `.github/`, `.githooks/` | Tests, this repository's gate and version check, continuous integration and the release | no |

## Rules

- **Public-safe from the first commit.** No tracker keys, machine paths, private repository names, personal names beyond the licence's copyright line, e-mail addresses or credentials: in files, file names, branch names and commit messages. `scripts/public_safe_gate.py` checks what it can; names are the author's and the reviewer's job. History is never rewritten after publication, so a leak cannot be undone.
- **Standard library only, Python 3.9 or later**, for the launcher, the resolver, `init`, `doctor` and the git hooks. Code that needs a package runs in the plugin's own environment, which does not exist yet.
- **`init` never overwrites, changes or appends to an existing file**, and never reads or writes a root `CLAUDE.md`. The one exception is `init --refresh-launcher`, which rewrites only `.meta-os/`.
- **The instance template is plain files.** A file in `plugin/instance-template/root/` lands at the same path in the instance. A file that would act on this repository is stored under another name (`gitignore`) and mapped in `init.py`. Config, settings and the packs file are generated by code.
- **The only framework code inside an instance is `.meta-os/`** (launcher, resolver, hook body). Keep it small; bump `.meta-os/VERSION` when it changes.
- **Nothing outside a session names a path inside the plugin.** Hooks, jobs and scripts call `.meta-os/meta-os`.
- **The plugin declares no dependency on a pack.** A pack is a plugin the user chooses.
- **Tests are atomic**: one behaviour and one input each, written as a matrix that grows by itself when a case is added. Tests build scratch instances in temporary folders and never read the developer's own Claude Code configuration.
- **Versions are written once.** The runner label, the Python versions and the tool versions each appear once in `.github/workflows/ci.yml`; `release.yml` only calls that file.
- **A change under `plugin/` raises the version.** `version` in the manifest must be above the last `meta-os--v*` tag (0.1.0 while there is none); `scripts/plugin_version.py check` refuses the pull request otherwise. The README's preview note names the same `major.minor`.
- **A release is the `release` workflow and nothing else.** It runs the checks, sets the version, and tags with `claude plugin tag`. No tag is made by hand and the workflow never pushes to `main`.
- **Inside the plugin, a file is named by a path that survives installation.** A `SKILL.md` names a file outside its own folder as `${CLAUDE_PLUGIN_ROOT}/…`; a reference document links its neighbours by relative Markdown links. No wikilink into `systems/`, `skills/` or any other framework path: an instance holds none of them. `tests/test_content.py` checks every such path.
- Files stay under 1,000 lines. Markdown is one line per paragraph.
- Commit messages: `<type>(<scope>): <description>`, with no attribution trailer.

## Check before committing

```
python3 tests/run.py
/usr/bin/python3 tests/run.py             # the floor, where the system Python is 3.9
claude plugin validate plugin --strict
claude plugin validate . --strict
python3 scripts/public_safe_gate.py tree
python3 scripts/plugin_version.py check --base origin/main
```
